# Описание подхода и его реализация

## 1. Три режима на одной матрице

| Режим | Что делает | Зачем нужен |
|---|---|---|
| **A** — по основной метрике | победитель по одной метрике качества | то, что делают на практике; baseline |
| **B** — классический TOPSIS | Hwang & Yoon, векторная нормализация, без ограничений | стандартный MCDM baseline |
| **C** — CP-TOPSIS-R | ограничения → Парето → TOPSIS → анализ устойчивости | известные компоненты, исследовательский baseline |
| **D** — фиксированные шкалы | ограничения → полезности на шкалах, заданных до сравнения → TOPSIS с фиксированными идеалами → анализ устойчивости | исследуемая модификация (H4) |

Режимы считаются одновременно, и интерфейс показывает, совпадают ли их победители.
Существующий механизм выбора чемпиона ModelArena не заменяется: он остаётся в ModelArena,
а режим A в DataArena его воспроизводит для сравнения.

## 2. Псевдокод режима C

```
вход: критерии (направление, вес ≥ 0), альтернативы (значение | ∅, σ | ∅),
      ограничения, нормализация, S, seed, κ, h, θ
1  проверить вход (веса конечны и ≥ 0, Σw > 0, ключи уникальны, ≥ 2 альтернатив)
2  w ← нормированные веса оцениваемых критериев
3  для каждой альтернативы:
       если есть ∅ по оцениваемому критерию → статус incomplete
       иначе если нарушено ограничение     → infeasible
       иначе если ограничение не проверить → unverified
       иначе                               → feasible
4  F ← feasible; если F пусто → «рекомендации нет», конец
5  P ← недоминируемые в F; остальным статус dominated + список доминирующих
6  ранжирование ← TOPSIS(P, w)
7  устойчивость:
       интервалы весов на сетке h
       локальная доля: S сценариев w ~ Dir(κw), seed
       глобальная доля: S сценариев w ~ Dir(1), seed+1
       шум: S сценариев x + N(0, σ²), seed+2 (если есть σ)
8  вердикт по min(локальная доля, доля при шуме) и порогу θ
9  объяснение: сравнение победителя со вторым по каждому критерию,
              границы весов, за которыми меняется лидер
10 предупреждения: двойной учёт качества, корреляция критериев,
              расхождение заявленного веса и фактического влияния
```

## 2a. Псевдокод режима D

```
1–3  как в режиме C (проверка входа, веса, статусы допустимости)
4    шкала каждого оцениваемого критерия: пользовательская | естественная | бюджет | по данным
5    u_ij ← полезность x_ij по шкале j (линейная или логарифмическая), обрезка до [0, 1]
6    D⁺_i = ‖w ⊙ (1 − u_i)‖, D⁻_i = ‖w ⊙ u_i‖, C_i = D⁻_i / (D⁺_i + D⁻_i)
7    ранжирование допустимых по C_i
8    устойчивость: интервалы весов, доля сценариев весов, шум измерений (ранкер — шаги 5–6)
9    предупреждение, если какая-то шкала взята «по данным»
```

## 3. Где это в продукте

**Backend** (слои соблюдают правило `api → services → domain`, проверяемое
`tests/unit/test_import_graph.py`):

| Файл | Назначение |
|---|---|
| `backend/domain/decision/models.py` | описание задачи, валидация |
| `backend/domain/decision/topsis.py` | TOPSIS, ранги с ничьими |
| `backend/domain/decision/pareto.py` | доминирование |
| `backend/domain/decision/sensitivity.py` | интервалы весов, Дирихле, шум |
| `backend/domain/decision/analysis.py` | режимы A–D, влияние, объяснение, предупреждения |
| `backend/domain/decision/scales.py` | шкалы режима D, полезности, близость к фиксированному идеалу |
| `backend/domain/decision/importers.py` | лидерборд ModelArena, JSON-матрица, CSV |
| `backend/adapters/modelarena/client.py` | чтение прогонов ModelArena по HTTP (только адрес из настроек) |
| `backend/services/decision.py` | сборка задачи из запроса |
| `backend/api/routes/decision.py` | `POST /api/decision/evaluate`, `POST /api/decision/import`, `GET /api/decision/modelarena/runs[/{id}]` |

**Frontend:** раздел «Decision Lab» (`frontend/src/features/decision/`): загрузка
матрицы, профили приоритетов, веса с мгновенным пересчётом, ограничения, выбор моделей,
вердикт, сравнение режимов, ранжирование, график компромисса, полосы устойчивости весов,
доли сценариев, «заявленный вес ↔ фактическое влияние», матрица измерений,
экспорт JSON/CSV/Markdown.

## 4. Связь с ModelArena

ModelArena не изменялась. DataArena читает лидерборд одного прогона
(`GET /api/arena/runs/{run_id}/leaderboard`) — по адресу из переменной
`DATAARENA_MODELARENA_URL` либо из файла, сохранённого из этого endpoint. Берутся:
метрики кросс-валидации с разбросом по фолдам, `elapsed_seconds` (wall-clock всего
процесса участника) и `model_bytes` (размер `model.joblib`).

**ModelArena не измеряет время инференса и память.** Эти значения не выдумываются:
они либо добавляются CSV-столбцом, либо измеряются стендом
`scripts/research/measure_models.py`. Предлагаемая процедура для ModelArena
(не реализована): после финального обучения замерить `predict_proba` на holdout
медианой 5 повторов в пересчёте на 1000 строк и записать в манифест артефакта вместе
с версией Python/библиотек и процессором.

Dataset Package v1 не изменялся.

## 5. Воспроизводимость

Отчёт JSON содержит вход (`input`) целиком: повторный `POST /api/decision/evaluate`
с ним даёт идентичный результат (проверено тестом `test_analysis_is_deterministic_for_seed`).
В отчёт входят версия метода `cp-topsis-r/2` (с режимом D), seed, число сценариев, κ, шаг сетки
и SHA-256 входа.
