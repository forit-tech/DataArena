# Аудит тестового набора

**Дата:** 2026-09-11
**Исходное состояние:** 610 случаев pytest из **312 тестовых функций** (остальное —
развёртка параметризаций), 69 случаев vitest.

Цель — не число. Цель: каждый оставшийся тест должен отвечать на вопрос «какую
реалистичную поломку он обнаружит, которую не обнаружит остальной набор». Там, где
ответа нет, тест уходит.

**«610 тестов» — не достоинство, а симптом.** Из них 298 случаев приходятся на 40
параметризованных функций; половина этих вариантов умирает на одном и том же механизме,
который уже доказан отдельно и покрыт мутацией.

---

## Метод

Классификация по назначению, а не по размеру:

| Класс | Что защищает | Решение |
|---|---|---|
| PRODUCT CONTRACT | наблюдаемое поведение API и интерфейса | оставить |
| DOMAIN INVARIANT | инвариант данных или вычислений | оставить |
| REGRESSION | конкретный найденный дефект | оставить один на дефект |
| SECURITY / ISOLATION | граница безопасности и ресурсов | оставить, ужать перечисления |
| INTEGRATION | взаимодействие настоящих компонентов | оставить немного и сильных |
| BOUNDARY | значимая граница алгоритма | оставить у настоящих порогов |
| DUPLICATE | то же нарушение ловит другой тест | удалить |
| ENUMERATION | перечисление членов класса, доказанного целиком | свести к представителям |
| TRIVIAL / LOW VALUE | не упадёт при реалистичной ошибке | удалить |

Главный критерий для перечислений: **если существует тест, доказывающий свойство
для всего класса, перечисление членов этого класса — документация, а не защита.**
Документацию оставляем в живой сквозной проверке, где она ничего не стоит.

## GAPS — риски, не покрытые ничем

Найдены по ходу аудита и не связаны с количеством тестов.

1. ~~**Отчёт Health при смене артефакта.**~~ **Закрыт по ходу чистки, и не по плану.**
   Добавленные мутации «не пересчитывать при смене артефакта» и «не пересчитывать при
   смене версии проверок» **выжили** на тогдашнем наборе — ровно тот пробел, который
   этот пункт и предсказывал. Закрыт тремя тестами в `tests/unit/test_health_checks.py`
   (смена артефакта, смена версии проверок, отсутствие лишнего пересчёта); обе мутации
   теперь ловятся.
   **Остаётся открытым смежное:** отпечаток читается из записи датасета, а не из файла,
   поэтому артефакт, подменённый в обход DataArena, отдаст старый отчёт как актуальный.
   Это вход для враждебного разбора, а не для чистки.
2. **Одновременные запросы Health.** Два параллельных запроса к несосчитанному отчёту
   не проверены: возможна двойная работа или гонка записи в кэш.
3. **Health на нечитаемом артефакте.** Есть проверка исчезнувшего файла; повреждённого
   содержимого — нет.
4. **Граница выборочности.** Порог `APPROXIMATE_CARDINALITY_CELLS` проверен подменой
   значения, но не на значениях ровно у границы.
5. **Устойчивость порядка находок между процессами.** Проверена внутри одного процесса.

Эти пробелы — вход для враждебного разбора Health, который идёт следующим. Закрывать их
в рамках чистки я не буду: иначе получится «удалили 100 слабых, дописали 100 новых».

**Чего я не делал.** Не резал набор до красивого числа. 610 → 80 получилось бы только
выбрасыванием границы исполнения SQL и регрессий разбора — ровно того, что однажды
поймало CRITICAL. Настоящий жир был в перечислениях и дублях, и он вырезан весь.

## Правило проекта

Новый тест обязан отвечать на вопрос: **какую реалистичную поломку он обнаружит,
которую не обнаружит существующий набор?** Ответ «он проверяет эту функцию» —
не ответ. Перечисление членов класса допустимо только там, где нет теста,
доказывающего свойство для всего класса.
